# 개발·검증·배포

## 작업 흐름
`master` → 작업 브랜치 → PR → `ci / gate` → 소유자 검토·직접 squash merge.
GitHub 브랜치 보호는 레포 설정에서 관리합니다. CI 파일을 병합한 후부터 기본 브랜치 push에도 검증이 실행됩니다.

## 안전한 검증 명령
새 checkout에서 개인 `.env`와 운영 자격증명 없이 실행합니다. 의존성 설치 시 자동 실행 스크립트를 차단합니다.

```sh

python3 scripts/ci/check_source.py
```

## 검증 범위
정적 구문 검증은 기능 테스트를 대체하지 않습니다. 이 레포에는 검증된 자동 기능 테스트가 아직 없습니다.
기존의 `test`라는 이름이 붙은 운영 점검 스크립트나 placeholder 명령은 자동 실행하지 않습니다.
검사는 실패를 그대로 보고하며 CI 실패·취소·필수 job 건너뛰기는 최종 gate 실패로 처리합니다.

## 배포
이 PR은 실제 운영 배포를 실행하지 않습니다. Render 서비스는 이 CI가 기본 브랜치에 병합되고 통과한 후 관리자 설정의 After CI Checks Pass로 연결해야 합니다. 현재 외부 서비스 설정은 이 파일만으로 변경되지 않습니다.
배포 대상은 검사한 커밋 SHA/이미지로 고정하고, 핵심 기능 smoke 확인 후 이상 시 이전 검증 버전으로 복구합니다. 앱 rollback과 데이터 migration rollback은 별도입니다.

## 추가할 테스트
변경 기능에 대해 외부 의존성을 mock한 단위 테스트, 임시 DB를 쓰는 통합 테스트, 사용자 핵심 흐름 smoke를 추가합니다. 운영 API 실호출이나 GPU 작업은 비용·권한이 제한된 별도 검증 환경에서만 수행합니다.
